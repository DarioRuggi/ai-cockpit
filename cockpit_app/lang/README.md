# Languages of Cockpit

Cockpit shows its own interface in the language chosen under **Settings → the translate button**.
English is the default and is always complete.

## Add or fix a language — the easy way

Open the language menu (the translate icon under the clock) and choose **Translate Cockpit…**: every text with its English, a progress bar,
search, a check of the `{placeholders}`, **Save**, **Use this language**, **Download my file** and **Upload a file**. No file editing needed.
To have a language included in Cockpit for everybody, **Send it to us** in the Studio opens https://cockpit.ruggi.site/translate.php.
The rest of this page is the by-hand way and the format.

## Add or fix a language — by hand

1. Download `_template.json` (the menu has a link, or copy it from this folder).
2. Save it as `<code>.json` — `fr.json`, `pt-BR.json`, `de.json`.
3. Fill in `_meta`: `code`, `name` (in English), `native` (in the language itself),
   `dir` (`ltr` or `rtl`) and `translator` (your name).
4. Type your text into the empty values. The `…#en` line under each key is the English, for reference.
   Leave a value empty to keep English there — a half-finished translation works.
5. Keep `{placeholders}` such as `{s}` or `{why}` exactly as written; they are filled in by Cockpit.
6. Put the file in **`<cockpit_data>/lang/`** (the menu shows the exact folder). That folder survives updates;
   the shipped `lang/` folder does not take new files (it is root-owned and guarded).
7. Reload. Your language appears in the menu. To try one without choosing it: add `?lang=fr` to the address.

A file in your folder with the same code as a shipped language overrides only the keys it fills in.

## Which languages

A language can be a Cockpit language when it is written horizontally, left-to-right or right-to-left. Languages that are normally written vertically are supported through their horizontal form; their writing system is supported in content (chats, notes, files). There is no vertical reading mode.

## For developers

`en.json` and `_template.json` are GENERATED by `php Installs/lang_extract.php` from the code: markup
`data-i18n="key"` / `data-i18n-title="key"` / `data-i18n-placeholder="key"`, script `T('key', 'English', {vars})`,
and the id of each tour step (`tour.<id>.title` / `.text`). Do not edit them by hand. The build runs
`lang_extract.php --check` and fails if they are stale or a pack changes a `{placeholder}`.
Right-to-left packs set `data-lang-dir="rtl"`; the layout is not mirrored.

### Adding new interface text

Write the HTML normally, then run `php Installs/lang_annotate.php` — it marks every visible text, `title=` and
`placeholder=` in `index.html` as translatable (idempotent, and it proves it changed nothing else), and
`php Installs/lang_extract.php` regenerates `en.json` / `_template.json`. Text built in JavaScript uses
`T('key', 'English', {vars})`; `php Installs/lang_annotate_js.php` converts `appendSystem('…' + x)`, `appendError`, `alert`, `confirm` and
`.textContent/.title/.placeholder = '…'` automatically (and proves the English output is unchanged). Icon ligatures (`material-symbols…`) are never marked.
